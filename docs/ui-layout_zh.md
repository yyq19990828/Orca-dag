# 可读的任务编排布局

[English](ui-layout.md) | 简体中文 · [文档导航](README_zh.md)

## 目标与决策

帮助操作者依次回答：现在发生了什么、哪些事项需要我决策、涉及哪个任务或执行者、
状态由什么证据支持。保留现有纸张、蜡笔风格，桌面端以画布为主，并在移动端（≤760px）
提供无障碍任务列表（TaskList）作为默认可读视图。复用 React 状态、原生折叠控件与
CSS，不引入新依赖或后端协议。

| 阅读层次 | 界面位置 | 内容 |
| --- | --- | --- |
| 定位 | Run 顶栏与任务概览 / 任务列表 | 当前目标、完成进度、六类任务数量、过期快照提示；移动端默认提供可读垂直任务列表 |
| 操作 | 运维：决策与恢复 | 待办汇总、审批、中断启动与恢复 |
| 执行 | 运维：执行与工作区 | 任务名称、存活状态、终端状态、主机与模型、工作区通道 |
| 证据 | 运维：历史与诊断 | 可读的操作历史、展开后查看完整标识、运行时能力 |
| 任务结果 | 阶段详情，配置项之前 | 报告摘要、正文、文件，或按字段与列表展示任意 JSON |

最小实施方案是将现有面板分组，不添加路由或重复操作控件。待办链接自动切换到正确分类，
并聚焦现有控件；执行记录定位会清除冲突的筛选条件。运维由顶部独立按钮打开，不再属于“动态 / 聊天”内部标签。两类面板复用可调整宽度的侧栏，切换时保留通信标签的选择。分类状态仅保存在当前页面。
Run 范围、启动锁、权限、轮询保护以及“请求配置 / 实际观察”的区分继续沿用现有规则。

## 展示规则

- 已知操作和终端代码提供中英文名称；未知代码原样保留。翻译不会授予权限或推断完成。
- 请求的 `absent` 表示运行时无记录，不代表操作一定未发生。
- 从当前 DAG 解析任务名称。完整任务、派发、请求和 Run 标识放入展开的证据区域；
  无法解析名称时回退到 ID。
- 结构化结果保留 `false`、`0`、null、空集合、未知字段、数组与嵌套对象。
  嵌套集合通过原生折叠控件查看。
- worker 报告的字段先检查类型再格式化。长正文与诊断信息分别展开，原始 JSON 保持可查。
- 保留纸张颜色和手绘标题；事实正文使用系统阅读字体，长值允许换行，计数采用等宽数字。
- 执行提示在顶栏中独占一行，不再覆盖导航。低于现有移动端断点时，侧面板继续使用应用的
  覆盖布局；分类按钮在三个等宽列内换行。

- 四种明确区分的读取状态，避免将网络或服务异常误当成空数据：
  1. *正在读取（Loading）*：初次加载进行中，展示专属 loading 状态。
  2. *首读失败（First-read failure）*：当前 Run 尚无成功读取的任务快照，或尚未选择 Run 时初次列表读取失败。显示明确错误、可展开的技术详情与重新加载页面入口；未取得任务数据时，启动前检查与执行不可用。
  3. *确认为空（Confirmed empty）*：Run 列表或 DAG 快照正常返回且数量为 0。展示明确的空状态引导，与加载中或失败截然分开。
  4. *陈旧快照（Stale snapshot）*：已有同一 Run 的成功快照，但后续刷新失败。保留任务与计数，提示数据可能过期，并允许查看详情。“**重试读取**”只刷新投影，不重放启动或其他变更，也不刷新全页。
  `RunPicker` 对外暴露首读状态（`RunListReadState`: `loaded`, `error`），使顶层视图能准确区分“空工作区”与“读取失败”。
- 键盘操作与抽屉焦点管理：
  - 在选中的 DAG 节点上按 `Enter` 或 `Space`，即可打开该阶段详情抽屉（`NodePanel`）。
  - 抽屉打开时，焦点自动移动至标题（`h3.node-panel__title`，`tabIndex={-1}`），方便屏幕阅读器和键盘操作者迅速定位。
  - 在 `NodePanel` 内按 `Escape` 键，抽屉安全关闭，并在下一帧（`requestAnimationFrame`）将焦点精确恢复至触发该抽屉的原节点元素。
  - 抽屉内部嵌套的交互控件（如选择 harness 或模型的 `DoodleSelect` 下拉菜单）优先拦截消费自身的 `Escape` 键，仅关闭自身下拉面板并将焦点归还其触发按钮，绝不误关闭外层阶段详情抽屉。
- 移动端响应式呈现与有界浮动菜单：
  - 在宽度 `≤760px` 时，主工作区默认切换为垂直无障碍 `TaskList`，展示任务名、状态圆点与就绪/阻塞原因，替代移动端难以操作的画布漫游。顶栏提供切换开关，可在任务列表与 DAG 图之间自由切换。点击列表项打开详情抽屉，关闭后同样恢复焦点至该项。
  - 执行配置与调度保持“桌面端优先”；移动端定位为可读的巡检、查看与应急响应，不承诺与桌面端完全对等的复杂编排操作能力。
  - 在宽度 `≤1024px` 时，三处浮动菜单（Run 选项面板 `.runpick__menu-panel`、视图面板 `.view-menu__panel`、执行设置面板 `.exec__settings-panel`）统一由局部悬浮窗切换为视口有界 sheet（`position: fixed`，四周受限于安全区内边距 `max(8px, env(safe-area-inset-*))`，最大高度 `calc(100dvh - 16px)` 并支持内部纵向滚动）。
  - 在 `≤1024px` 下，每个 sheet 均显示显式的关闭按钮（`.menu-close`，满足最小 44px 触控区高度）。
  - 打开视图菜单时，通过 `.app .dag-toolbar:has(.view-menu[open]) { z-index: 40; }` 提升工具栏层叠上下文，避免被紧凑顶栏遮挡，确保关闭按钮可点击。
  - 按 `Escape` 可直接关闭打开的菜单，并将焦点归还至对应的 `summary` 触发元素。
- 结构化启动前检查（Preflight Launch Preview）：
  - 启动前检查（`LaunchPreview`）在执行前清晰呈现完整启动计划：
    - 请求的默认执行器与最大并行度在顶部展示一次；只有涉及 OpenCode 时才显示其默认界面。
    - 所有任务共有的限制（Common limits）在顶部去重汇总展示一次，避免各任务逐条重复刷屏。
    - 展示完整任务名，名称缺失时回退到精确 ID；展开任务可查看或复制完整 ID，剪贴板拒绝时明确提示手动复制。
    - 存在不支持路径、未知路由/限制代码、或包含任务特有额外限制的任务，标记为待核对状态并默认自动展开（`open={needsReview || undefined}`）。
    - 每个任务下方清晰罗列该任务单独请求的配置覆盖（harness、模型、effort、保留设置、放置、环境、lane、OpenCode 界面）。
  - 对话框（`DecisionDialog`）承载启动前检查与确认：
    - 支持独立于文本消息的自定义内容（`content`）渲染。
    - 具备详情感知（details-aware）的焦点陷阱（`trapKeys`），Tab 键循环仅在当前可见的表单与展开的 `<details>` 内流转，自动跳过折叠隐藏的元素。
    - 安全取消：点击“暂不”、按 `Escape` 或点击遮罩，不调用 `POST /api/run`。准备预检时已经保存的配置不会因取消而回滚。
    - 严格声明权威边界：预览仅为当前配置意图的只读检查与预排版；“预览不等于验证执行”，不代表模型可用性、agent 就绪状态或实际执行已获验证。工作区放置设置也不负责建立外部测试运行时。

## 实施与验收

`App.tsx` 协调读取状态、窄屏视图、菜单与详情焦点；`DagView`、`NodePanel` 和
`DoodleSelect` 共同维持键盘激活与嵌套 Escape 规则。`TaskList` 提供窄屏任务索引，
`RunPicker` 提供首读状态。`LaunchPreview` 在现有 `DecisionDialog` 内呈现请求默认值、
共有限制与精确任务证据；`ExecControls` 仍要求明确确认后才启动 Run。

Worker 与请求摘要继续复用 DAG 名称映射，`ResultSummary` 和 `StructuredData` 保留
报告内容与原始证据。样式在既有主题上补充 `read-state.css`、`task-list.css` 和
`launch-preview.css`，所有新增文案保持中英文成对维护。

仓库检查命令为 `npm run check`。macOS 上，现有 socket 测试需要较短且经过规范化的临时路径：
`TMPDIR=/private/tmp npm run check`。这样可避免 Unix socket 路径截断和 `/tmp` 与
`/private/tmp` 不一致的问题。

可重复的浏览器检查使用 Playwright CLI，并拦截全部 API 请求：

```sh
npm run dev:web
# 在另一终端执行，需要已有 Playwright CLI：
mkdir -p output/playwright
playwright-cli open http://localhost:5173
playwright-cli run-code "$(cat scripts/check-ui-layout.js)"
```

脚本 `scripts/check-ui-layout.js` 保留为最初的自动化布局验收脚本。检查覆盖中英文、1280/900/620/375/320 像素宽度、桌面与移动端结果面板、审批与执行记录定位、带筛选的执行记录定位、无记录请求的含义、嵌套与假值、异常报告字段、文本转义、完整报告，以及页面和面板溢出。截图保存于 `output/playwright/`。这些是界面验收数据，不构成真实 worker 执行证据；另已只读检查真实 Run 数据，没有启动或停止 worker。注意：`scripts/check-ui-layout.js` 并不覆盖五项新增的交互路径（键盘节点激活、四种读取状态、移动端任务列表切换、有界菜单 sheet 或结构化启动前检查）。

### 五项优化的针对性人工验证清单

针对本次五项 critique 优化，应通过人工核验以下交互路径：

1. **键盘节点激活与抽屉焦点/Escape**：
   - 使用 Tab 聚焦 DAG 节点，按 `Enter` 或 `Space`：阶段详情打开。
   - 确认抽屉标题（`h3.node-panel__title`）立即获得焦点。
   - 按 `Escape`：抽屉关闭，焦点平滑归还至触发该抽屉的 DAG 节点。
   - 打开抽屉内的嵌套 `DoodleSelect`（如模型或 harness 下拉菜单），按 `Escape`：下拉菜单关闭，焦点保留在选择器触发按钮上，外层抽屉保持打开。
2. **四种读取状态与只读重试**：
   - 首次加载期间验证 Loading 指示，不虚报空数据或失败。
   - 模拟首读失败：验证首读失败画面展示错误详情与页面刷新按钮；启动前检查与 Run 按钮被禁用（不显示虚假的空列表或陈旧快照）。
   - 验证确认无 Run 或无任务时展示专属的明确空状态引导。
   - 模拟已获取有效快照后的周期性刷新失败：验证既有任务与计数保持显示，出现过期快照提示条与技术详情，点击“重试读取”按钮可刷新投影，不刷新页面且不重放变更。
3. **移动端任务列表与图切换（≤760px）**：
   - 在 ≤760px（如 375px）视口下，验证主界面默认呈现可读 `TaskList`。
   - 切换“依赖图”与“任务列表”，验证两种视图均可进入。
   - 点击/激活任务项：阶段抽屉正常弹出；关闭抽屉后焦点经 `rAF` 恢复至任务项。
   - 确认执行配置仍以桌面端为主，移动端以安全可读巡检为主。
4. **有界菜单 sheet 与关闭按钮（≤1024px）**：
   - 在 ≤1024px 视口下分别展开 Run 选项菜单、视图菜单与执行设置菜单。
   - 验证三处菜单均呈现为视口有界 sheet（贴合安全边距，最大高度 `calc(100dvh - 16px)`，支持内部滚动）。
   - 验证各 sheet 均呈现明显的“关闭”按钮（`.menu-close`，满足最小 44px 触控区）且功能正常。
   - 验证视图工具栏层叠上下文已提升（`z-index: 40`），视图菜单的关闭按钮可正常点击，不被顶栏遮挡。
   - 验证按 `Escape` 可关闭菜单并将焦点交还给对应 `summary`。
5. **结构化启动前检查**：
   - 点击“启动前检查”或“Run with Orca”打开检查对话框。
   - 验证共享默认设置与去重后的共有限制汇总于顶部展示。
   - 验证任务列表展示完整任务名称、精确任务 ID 与路径/原因。
   - 验证存在不支持路径、未知代码或任务特有限制的项自动展开以供核对。
   - 点击任务旁的“复制 ID”按钮：验证提示切换为“ID 已复制”（剪贴板权限受限时优雅提示手动复制）。
   - 在 `DecisionDialog` 中按 Tab / Shift+Tab 轮询：验证焦点陷阱只在可见控件间循环，严格跳过折叠 `<details>` 内的内容。
   - 在启动确认中点击“暂不”或按 `Escape`：不调用 `/api/run`；准备预检时已保存的偏好仍保持保存。

### 证据边界

这些检查使用 Chromium 视口模拟与隔离 UI API 数据；双语宽度矩阵覆盖
1280、900、620、390、375 和 320 像素。可通过合成的原生触摸输入检查列表点按与
滑动，但这不代表真机或 Safari 验证。界面样例不证明真实 Orca worker 执行，
也不构成完整 WCAG 合规认证。

全树样式检测仍会提示既有 Chat／待办区域的侧边装饰及蜡笔弹性曲线。本轮五项交互
修复保留这些原有装饰；界面烟测通过不代表全部历史样式都已达到检测器零提示。

回退仅涉及前端源文件与检查、文档，无需数据库、配置格式、发布、提交或外部状态迁移。

## 聊天阅读优化

沟通中心保留纸张配色与手绘标题，会话正文和输入框改用局部系统阅读字体。正文为
`1rem`（通常 16px）、1.65 行高；时间等元信息为 `0.8125rem`（13px），辅助说明为
`0.875rem`（14px），会话标题保持 18px。消息最大阅读宽度为 65ch，不再让气泡始终
挤在会话区域的一小部分。完整任务与报告继续按需展开，内部滚动阅读区增高。

- 侧栏宽度不超过 640px 时，会话列表移到消息区上方，可水平滚动；更宽时保留双列。
  长会话标题最多展示两行，完整文本仍可通过可访问名称和悬停提示读取。
- 手机宽度不超过 620px，或窗口宽度不超过 900px 且高度不超过 600px 时，打开的
  动态/聊天视图使用完整视口。被覆盖的主界面控件不参与键盘导航，但不丢弃 DAG
  布局。关闭后焦点返回入口；打开阶段时让位给任务详情，关闭详情后恢复原会话及
  焦点。桌面继续保留并排查看任务详情的行为。
- 输入区沿用原有发送、回复、权限和快捷键逻辑。输入文字为 16px，保留明显焦点；
  底部区域限制高度并可滚动，避免群发配置挤占全部消息空间。只有成功的
  `worker_done` 使用完成底色，失败报告沿用错误配色。

使用真实已存 Orca 会话，分别在中英文下验证 1440×1000、1024×900、720×500、
390×844 和 320×640，并实测侧栏拖动。检查包括水平溢出、长任务阅读、证据展开、
键盘关闭与焦点返回，以及手机上的阶段详情切换和返回。输入状态与中英混排长标识符
使用检查后立即移除的本地 DOM 探针；没有发送消息、更改 Run 数据或启动 worker。
抽样消息正文、元信息、链接和占位文字达到 4.5:1 对比度。这是 Chromium 视口证据，
不代表真机、Safari 或完整 WCAG 合规认证。机械检测仍提示既有状态色条与蜡笔弹性
曲线；这些身份及状态表现并非本轮新增。

## 节点启动配置

节点详情按配置依赖顺序展示：Agent / harness、模型、支持的推理强度，再到 OpenCode
启动界面。不改变启动路径、版本验证门槛或已派发 Task 不可变的原始启动计划。

- OpenCode 默认只显示一个可搜索的模型选择器。“手动输入模型”按需打开输入框并聚焦；
  选择建议或默认模型后收起输入框。无论当前值是否出现在建议列表中，都保留正确显示。
  模型发现仍只是本地查看器工作区范围内的建议。
- 建议加载中、列表为空或获取失败时，默认与手动输入仍可用。不完整的 OpenCode 输入
  显示关联的格式说明，不替换已保存选择；模型和 variant 标识保持原样。清空 OMP 模型
  仍会保留不支持的已存 effort，直到用户明确清除。
- 启动字段采用局部系统阅读字体：控件 14px，文本和搜索输入 16px，说明 13px。
  锁定字段仍禁用，但通过可读文字与虚线边框表示只读，不再整体淡化或显示下拉箭头；
  锁定原因继续显示。兼容性、发现范围与模型路径说明按需展开，Mini 权限提醒和阻止
  启动的 effort 警告仍留在表单中。
- 滚动时状态与关闭按钮保持可见。宽度不超过 620px 的手机，或宽度不超过 900px 且
  高度不超过 600px 的短窗口，使用视口查看详情；被遮挡控件不参与键盘导航。调整
  窗口大小时，详情优先于已打开的聊天，普通桌面则保留并排查看。

使用真实只读节点，在中英文下检查 1440×1000、1024×900、720×900、720×500、
