# Orchestration Panel 双形态 UI 布局设计

[English](ui-layout.md) | 简体中文 · [文档导航](README_zh.md)

## 当前架构：四区黑白灰 IDE 工作台 + Orca 精简右侧边栏

**Orchestration Panel**（`web/src/main.tsx`）基于同一套前端代码，按 `?view=sidebar` 呈现两种互补形态：

1. **完整标签页工作台（`App.tsx`、`styles/ide-workbench.css`）**——支持深浅双主题（黑白灰 Zinc / Obsidian 配色，自动跟随 Orca 宿主主题并支持手动切换）的四区 IDE 工作台：
   - **顶部栏**：分叉汇聚 DAG 品牌图标（`DagBrandMark`）+ **Orchestration Panel** 标题、Run 选择器、Run 健康徽标、连接状态、全局命令面板（`⌘/Ctrl+K`）、快捷键指南、深浅色切换、语言切换（`中 / EN`）与主执行控制（`Run` / `Stop`）。
   - **A 区（左侧导航与实时舰队）**：实时舰队（Fleet）、决策门禁（Gates）、协调器状态卡以及 5 个舞台视图切换（`拓扑画布`、`状态泳道`、`Run 历史账本`、`工作区与清理`、`执行与运行时能力`）。
   - **B 区（中央主舞台）**：常驻懒加载 React Flow DAG 画布（支持 LR/TB 分层布局、缩略图、父子链开关、流式列表切换）或对应运维视图。
   - **C 区（底部可调高坞）**：`实时事件流`、`Worker 输出`（基于 `OutputTail` SSE 的 `WorkerOutputDockView`）与 `变更请求账本`。
   - **D 区（右侧可调宽上下文检视面板）**：审批门检视（`GateInspector`）或紧凑模式 `ChatPanel`（`.odag-inspector--compact-chat`），包含 4 个同级页签：**消息**（黑白灰聊天气泡 + 头像 + 统一自适应输入框）、**会话**（`NodeSessionPanel` 可折叠实时工具调用卡片）、**任务**（`NodePanel`）与**启动配置**。
2. **精简右侧边栏伴生面板（`SidebarApp.tsx`、`components/sidebar-app.css`、`?view=sidebar`）**——面向 Orca 原生 `orchestration-panel` 窄侧栏（`320–450px`）设计：
   - **紧凑双行顶栏**：Run 选择器、传送的 Run/Stop 图标按钮、**唯一**的 `↗ 标签页` 入口（`POST /api/open-tab`，智能复用或原地复活完整标签页）、原生 `<progress>` 进度条及横向状态筛选芯片。
   - **3 个主导航页签**：**任务**（状态图标、harness 胶囊、最新摘要）、**待处理**（审批门禁、Worker 提问、单次权限审批、停止事件与可恢复失败节点）、**活动**（最近实时动态）。
   - **单任务下钻详情**：顶部返回栏附带**聚焦终端**与**恢复会话**（L1 原生恢复）快捷按钮，下方 3 个同级页签在视觉风格与命名上与完整 Web 保持完全一致：
     - **消息**（`chat.view.messages`）：直接复用 `<ChatPanel embeddedMessagesOnly />` 与 `.odag-inspector--compact-chat` 样式，保证聊天气泡、头像、从 Task 历史恢复的初始简报、引用回复、运行态摘要与统一输入栏 100% 一致。
     - **会话**（`ide.inspector.tabSession`）：挂载 `NodeSessionPanel` 展示实时可折叠工具调用卡片。
     - **输出**（`sb.detailOutput`）：挂载 `WorkerOutputDockView` 查看原始终端/transcript 流。

## 前代浅色双区工作台设计记录（历史参考）

### 目标与决策

帮助操作者依次回答：现在发生了什么、哪些事项需要我决策、涉及哪个任务或执行者、状态由什么证据支持。
应用采用现代化、苹果风格的浅色双区编排工作台（`workbench.css`、`styles.css`、`chat-dock.css`、`graph-motion.css`），
彻底摒弃旧版深色控制台与 SVG 滤镜噪点，采用浅银灰表面、系统无衬线字体与响应式双区架构：
- **桌面端（左侧画布，约占 54%）**：常驻 React Flow 依赖图画布（`.workbench-canvas`），持久挂载展示任务拓扑依赖，
  避免画布重复挂载或视口组件遮挡。
- **桌面端（右侧操作区，约占 46%）**：可调节宽度的 App 式操作区（`.workbench-operations`），内置应用主屏幕启动器
  （`.workbench-nav--home`）、紧凑底部 Dock 导航栏（`.workbench-nav--dock`）、集成聊天应用（`.workbench-chat` 中的
  `ChatPanel`）及完整运维分节。在画布中点击节点直接进入对应 Task 的私聊 Messages 视图（标准节点路由 `#section=chat&task=<id>`），
  并在 Messages 与收件检查旁提供完整的 Task 详情与配置同级页签（`NodePanel`）。打开聊天时保持操作区面板宽度，
  不会挤压出第三列或压缩 DAG 画布。
- **移动与平板端（≤900px）**：顶部提供专属分栏切换器（`.workbench-mobile-switch`），支持在画布（`taskView.graph`）与
  应用操作区（`workbench.home`）之间一键切换。在画布中点击节点自动切换至操作区展示该 Task 的私聊会话；分栏切换器支持切回画布。

主页、聊天与六个运维分节统一使用 URL Hash 路由（`#section=home`、`#section=chat`、
`#section=<name>`，标准节点路由 `#section=chat&task=<id>`），支持浏览器前进/后退与按 Run 隔离的滚动记忆。
旧版 `#section=tasks` 路由规范化重定向至 Chat。刷新主页或聊天恢复对应应用。
选中任务打开其私聊 Messages 视图，并在轮询中保持稳定的 `taskSelection`。
操作区顶栏承载页面唯一可见的主标题 `h1`；ChatPanel 内部会话标题使用 `h2`。
`NodePanel` 无独立 `h1`、无关闭按钮、无 Escape 监听或自动聚焦；首次访问挂载并在后续同级页签切换中常驻。
## 展示规则

- 已知操作和终端代码提供中英文名称；未知代码原样保留。翻译不会授予权限或推断完成。
- 请求的 `absent` 表示运行时无记录，不代表操作一定未发生。
- 从当前 DAG 解析任务名称。完整任务、派发、请求和 Run 标识放入展开的证据区域；无法解析名称时回退到 ID。
- 结构化结果保留 `false`、`0`、null、空集合、未知字段、数组与嵌套对象。嵌套集合通过原生折叠控件查看。
- worker 报告的字段先检查类型再格式化。长正文与诊断信息分别展开，原始 JSON 保持可查。
- 苹果风格浅色设计系统代币：清晰的 1px 结构边框（`var(--line)` `#dcdce1`、`var(--line-strong)` `#c9cbd1`）、
  白色与浅银灰表面（`var(--paper)` `#ffffff`、`var(--paper-2)` `#f5f5f7`、`var(--paper-3)` `#eaecef`）、
  深色中性文字（`var(--ink)` `#1d1d1f`、`var(--ink-soft)` `#565b65`、`var(--ink-faint)` `#626771`）、
  苹果系统蓝操作高亮（`var(--sky)` / `var(--sky-ink)` `#0066cc`、`var(--sky-wash)` `#eaf3ff`），
  以及克制平衡的语义状态色彩：完成/成功绿色（`--meadow: #257344`）、就绪青蓝色（`--sky: #0066cc`）、
  挂起/派发琥珀色（`--butter: #92600d`、`--lilac: #6554a4`）、阻塞棕橙色（`--flame: #a45110`）、
  失败/错误红色（`--coral: #b83232`、`--blush: #b83232`）、中立退出灰色（`#64748b`）。严禁深色黑曜石底色、
  SVG `feTurbulence` 滤镜、位移噪点或外部网络字体。
- 预览与停止通过 portal 进入顶栏 `.workbench-action-host`，错误、回执和执行状态独占整行。
  启动/再次运行改为依赖图工具栏里的 40px 纯图标按钮（窄屏 44px），保留翻译后的无障碍名称、
  Tooltip、权限禁用和原有启动前确认。窄屏切换至依赖图后启动；停止仍在全局顶栏可见。
  Run 选择器填充顶栏剩余宽度，保留省略号截断与完整标题。
  桌面端使用单行控件；窄屏依次排列 Run/语言、执行控件、连接/进度，操作目标至少 44px。
  查看器页面不提供“新建 Run”按钮；Run 的创建归属于规划智能体或 CLI，
  查看器仅负责读取和协调已有 Run（服务端 `POST /api/runs` 接口保持公共开放且不变）。
- 连接状态使用链环或断开的链环图标，不显示文字。保留原有状态颜色、可聚焦状态语义及详细无障碍/悬停说明，
  区分未知、读取失败与执行禁用；链环图标不代表获得执行权限。

### 读取状态

四种明确区分的读取状态，避免将网络或服务异常误当成空数据：
1. *正在读取（Loading）*：初次加载进行中，展示专属 loading 状态。
2. *首读失败（First-read failure）*：当前 Run 尚无成功读取的任务快照，或尚未选择 Run 时初次列表读取失败。显示明确错误、可展开的技术详情与重新加载页面入口；未取得任务数据时，启动前检查与执行不可用。
3. *确认为空（Confirmed empty）*：Run 列表或 DAG 快照正常返回且数量为 0。展示明确的空状态引导，与加载中或失败截然分开。
4. *陈旧快照（Stale snapshot）*：已有同一 Run 的成功快照，但后续周期性刷新失败。保留任务与计数，提示数据可能过期，并允许查看详情。“**重试读取**”只刷新投影，不重放启动或其他变更，也不刷新全页。

`RunPicker` 对外暴露首读状态（`RunListReadState`: `loaded`, `error`），使顶层视图能准确区分“空工作区”与“读取失败”。其下拉面板保留历史分页与精确 Run ID 查询；规划/CLI 创建 Run，选择器仅读取既有 Run，本页不提供新建 Run 按钮。

### 键盘操作与 Task 私聊

- 在选中的 DAG 节点上按 `Enter` 或 `Space`，URL 更新至 `#section=chat&task=<id>`，在操作区进入该 Task 的私聊 Messages 视图。
- 在私聊会话中，操作者可在 **Messages**、**Task** 与**收件检查**三个同级页签间切换。完整的 Task 详情与启动配置（`NodePanel`）作为 Task 页签的内容展示，无独立 `h1` 或关闭按钮，保留原生的页签键盘交互。
- 嵌套的交互控件（如选择 harness 或模型的 `DoodleSelect` 下拉菜单）优先拦截消费自身的 `Escape` 键，仅关闭自身下拉面板。
- `NodePanel` 不拦截 `Escape`，亦不设置模态焦点陷阱；如需返回会话列表，可通过会话顶部的返回按钮（`chat__back`）返回。

### 响应式呈现与移动端分栏切换

- **桌面端双区布局（约 54% / 46%）**：
  - 左侧画布（`.workbench-canvas`）默认占据视口约 54% 宽度，保持 React Flow DAG 画布始终常驻挂载且支持交互。
  - 右侧操作区（`.workbench-operations`）默认占据约 46% 宽度，可通过垂直拖拽分割线（`.workbench-chat-resize`）平滑调节。宽度限制在 380px 至 820px 之间（`COMMUNICATION_MIN_WIDTH = 380`、`COMMUNICATION_MAX_WIDTH = 820`），并为左侧画布保留至少 320px 宽度（`CANVAS_MIN_WIDTH = 320`）。
  - 分割线支持左右方向键以 32px 步长调节，Home/End 跳到最小/最大宽度。ARIA 数值跟随实际渲染宽度及视口约束，而非最后一次拖动请求。
  - 打开聊天（`communicationOpen`）时直接复用操作区面板宽度，不额外开启第三列，亦不压缩 DAG 画布。
- **平板与移动端断点（≤900px）**：
  - 双栏布局收缩为单面板视图，通过顶部的专属分栏切换器（`.workbench-mobile-switch`）进行切换。
  - 两个互斥按钮支持在画布（`taskView.graph`）与操作应用（`workbench.home`）之间快速切换。
  - 从画布中点击任务节点时，系统自动将 `mobilePane` 切换至 `"operations"` 并展示该 Task 的私聊会话。
- **Radix 基础组件与流内设置**：
  - 统一使用 `radix-ui`，保留现有 CSS 视觉规范，不引入第二套主题或直接定位库。
  - 视图菜单与协调者健康详情使用 portal Radix Popover，负责边界碰撞、外部关闭与 Escape 焦点恢复；移除全局折叠菜单关闭监听。
  - `DoodleSelect` 对简单枚举使用 Radix Select，支持空字符串“使用配置默认值”及可读的已保存禁用选项。Run、模型、环境、lane、@Task 收件人等可搜索字段使用 Popover 加显式 combobox/listbox，保留名称、值、提示搜索，以及 Run 历史分页和精确 ID 查找。
  - Tooltip 描述关联到真正可聚焦的触发控件；禁用字段保留相邻原因说明，不增加多余 Tab 停靠点。
  - 执行设置保留设置分节内的原生流内折叠表单。与临时浮层不同，点击表单外部不会折叠设置。

### 结构化启动前检查（Preflight Launch Preview）

- 启动前检查（`LaunchPreview` 在 `DecisionDialog` 中承载）在执行前清晰呈现完整启动计划：
  - 请求的默认执行器与最大并行度在顶部展示一次；只有涉及 OpenCode 时才显示其默认界面。
  - 所有任务共有的限制（Common limits）在顶部去重汇总展示一次，避免各任务逐条重复刷屏。
  - 展示完整任务名，名称缺失时回退到精确 ID；展开任务可查看或复制完整 ID，剪贴板拒绝时明确提示手动复制。
  - 存在不支持路径、未知路由/限制代码、或包含任务特有额外限制的任务，标记为待核对状态并默认自动展开（`open={needsReview || undefined}`）。
  - 每个任务下方清晰罗列该任务单独请求的配置覆盖（harness、模型、effort、保留设置、放置、环境、lane、OpenCode 界面）。
- 对话框（`DecisionDialog`）承载启动前检查与确认：
  - 支持独立于文本消息的自定义内容（`content`）渲染。
  - Radix Dialog 负责焦点包含、页面滚动锁定及关闭。保留原有 Promise 队列、必填输入校验、优先聚焦安全取消按钮及队列结束后返回最初触发点的契约。键盘跳过折叠内容，嵌套选择器优先消费 Escape。
  - 安全取消：点击“暂不”、按 `Escape` 或点击遮罩，不调用 `POST /api/run`。准备预检时已经保存的配置不会因取消而回滚。
  - 严格声明权威边界：预览仅为当前配置意图的只读检查与预排版；“预览不等于验证执行”，不代表模型可用性、agent 就绪状态或实际执行已获验证。

### 动态流管理与代际防线

- **Activity SSE 事件流（`/api/activity/stream`）**：单条共享事件流在页面隐藏时（`document.visibilityState === "hidden"`）自动断开连接，通过受控的文档可见性事件与真实服务端 EventSource 验证，保留轨道收起期间的未读计数，并在恢复可见时自动重连与刷新。
- **代际标记防线**：详情与日志面板记录请求与选择代际标记（`generation.current`、`outputGeneration.current`），防止快速切换节点或 Run 时过期的异步响应覆盖新选中内容。

### 运维治理、标准流内面板与审批门

- **标准文档流**：运维卡片与面板（`.gates`、`LanesPanel`、`CleanupPanel`、`WorkerPanel`、`SchedulerPanel`）及 Task 配置面板（`.chat__task .node-panel`）均参与常规文档布局流（`position: static; width: 100%`）。全局 `.gates` 不再使用绝对定位，彻底消除了早期版本中 Lane 与 Cleanup 绝对定位坐标与中央主标题垂直重叠的缺陷。
- **概览与决策分级**：概览分节承载紧凑的待办操作摘要（`OperationsAttention` `variant="summary"`），显示待办计数与流内“打开决策”跳转按钮（`attention.openDecisions`）；决策分节承载完整交互列表（`variant="full"`），提供逐项聚焦定位与处理控件。
- **Lane 证据状态表达**：`LanesPanel` 在 Lane 证据尚未读取或不可用时显式展示待读状态提示（`lane.pending`：“通道证据尚未读取或不可用。”），避免无根据的假阴性推断。
- **Worker 舰队与派发标识**：`WorkerPanel` 展示清晰的 worker 属性、能力列与精确的 Dispatch 派发标识，移除重复的 Task ID 回退。进程退出报告为中立的 `exited` 存活状态（`#64748b`），仅表示进程终止，不推断成功或失败。
- **清理面板（`CleanupPanel`）**：提供按需候选审查（`review`），通过核验全局完整 fleet 列表（`listWorkers(undefined, { includeRemote: true })`）保护未在终端列表中的其他 Run Chat 及主/活跃工作区，要求逐项确认，并暴露原生安全删除已合并分支选项（`deleteBranch`）及 `preservedBranch` 证据。
- **规范审批门创建（`POST /api/gates`）**：Task 详情与配置面板（`NodePanel`）支持为同 Run 尚未派发的任务创建审批门，受 coordinator 生命周期锁保护。
- **显式控制确认**：对未处于当前 viewer 活跃调度下的 Run 发起一次性变更时，要求提供匹配当前 Run 绑定的显式控制确认（`coordinatorControl`），严格拒绝隐式接管。

### 内存与性能边界的客观表达

技术文档与性能评估中，必须严格区分 **V8 JavaScript 堆内存（JS Heap）** 与**浏览器渲染进程 / GPU 合成器内存**：
- JavaScript 堆内存衡量的是 V8 引擎内分配的 JS 对象与闭包大小。
- 渲染进程与 GPU 合成器内存（图层位图缓存、Canvas 绘图上下文、DOM 节点树底层结构）由浏览器底层与操作系统独立调度。
- 移除持续的 SVG 滤镜运算、消除永久动画循环、实施 DAG 画布懒加载减轻了 CPU 运算与合成器图层负担；但关于内存与性能的表述必须基于实测证据。当前未对 CPU、合成器或内存的量化节省进行基准测试或认证声明。历史 Run 533 基线测得 JS 堆旧值 5708840 / 新值 5769648，未产生 GPU 或渲染器总内存缩减。严禁仅凭 JS 堆内存测量数据推断 GPU 或渲染器总内存节省，亦不得把设计优化方案描述为实测性能收益。

## 聊天架构与共享 Task 消息

通信面板（`.workbench-chat`）集成于右侧操作区（`.workbench-operations`），直接复用操作区面板宽度（桌面端约 46%），不额外挤占视口或压缩左侧 DAG 画布。正文为 16px（`1rem`）、1.6 行高；元信息为 14px（`0.875rem`）或 12px（`0.75rem`），会话标题保持 16px 半粗体。发出消息采用苹果系统天蓝色底色（`var(--sky-wash)` `#eaf3ff`），接收消息采用柔和浅中性底色（`var(--paper-2)` `#f5f5f7`），错误报告采用浅粉底色（`var(--blush-wash)` `#fceeee`）。消息最大阅读宽度受到舒适约束，长标识符具备自动折行防护（`overflow-wrap: anywhere`）。

主页与 Dock 的聊天入口统一使用描边对话气泡图标。
Run 状态摘要（`.chat-runtime-summary`）只将状态与说明分行居中；上次检查时间和次数属于独立的「收件检查」，不占用消息时间线。

- **会话侧边栏（`.chat__sidebar`）**：
  - 228px 侧栏使用 Radix ToggleGroup 切换私聊/群聊列表。私聊搜索匹配已加载的任务名、精确 ID、harness 与模型，不改变选中收件人。
  - 私聊只包含 Task/Agent，不再展示 Run 控制。会话项显示头像、两行名称、任务状态、最近消息摘要及有证据的未读/优先级/待回复标记；未读仍是 Orca 收件箱证据，不代表操作者是否打开过会话。
  - 群聊分类先展示一个「Run 群聊」会话项；窄面板切换分类不会直接进入聊天。
  - 身份 Popover 展示完整 Task/Dispatch、模型信息及「打开阶段」入口；Escape 关闭后恢复信息按钮焦点。
- **Harness 头像**：使用 Claude、Codex（官方扩展采用的 OpenAI Blossom）、OpenCode、Oh My Pi、Antigravity 的本地官方图形；`opencode2` 复用 OpenCode。未知 harness 保留中性图标，群聊标题不借用最近发言者的品牌。
  [HarnessAvatar](../web/src/components/HarnessAvatar.tsx) 记录原始资源网址、MIT 说明与商标限制。公开资源不等于获得商标授权；不宣称许可或背书。相关 SVG 也保留随资源分发的 MIT 说明。
  聊天与 worker 列表共用按 Dispatch 隔离的身份补全：已结算 fleet 行省略 launch/provider 时，
  只使用精确匹配 Run/Task/Dispatch 的启动历史或 `worker-show` 的实际启动身份；
  不借用其他尝试的品牌或当前保存的默认 harness，无法证明身份时保持中性。
- **群聊与私聊共用消息**：
  - 同一 Run 的 Activity 事件构成两种视图。Task 消息显示 `@协调器`；群聊中发出的消息按事件实际目标显示 `@Task`。点击 Task 消息头像进入对应私聊。
  - 收到的消息显示任务名称与完整、可选中的 Task ID，实际观察到的 harness/model 作为次要信息。DAG 行不可用时使用消息自带的任务名或精确 ID；协调器消息仍显示协调器，不把目标 Task 冒充为发送者。
  - 使用可搜索的 Radix 收件人选择器显式选择 Task，复用私聊指导或该 Task 待回复问题的接口及协调权检查。不从最近发言者推断收件人、不改投其他 Task、不隐式 `@all` 广播；不可用目标不能发送。
  - 真实邮箱 status 消息进入聊天气泡，合成进度与心跳仍作为运行时信号。历史受众广播保留原始元数据；公共 HTTP 广播 API 不变，但不再驱动聊天输入区。
- **独立收件检查**：Radix Tabs 分开消息/输入区与 `MailboxChecks`；后者保留来源、耗时、投递/重放、错误、原始消息摘要及 agent 快照，只合并相邻兼容检查。两个页签保持挂载，隐藏页签不覆盖消息阅读位置。查看记录不发送 Orca ACK。
- **容器响应式（`@container chat-panel (max-width: 640px)`）**：先显示完整列表，点击进入单个会话，返回恢复同一私聊/群聊列表及选中项焦点。隐藏面板不可被键盘聚焦；断点依据面板宽度，不是整个视口。
- **阅读位置**：只有原本位于末尾时才跟随新记录；上翻后保持阅读位置。“回到最新”跳至末尾并聚焦历史区域，也覆盖有界时间线淘汰最早记录、总高度不变的情况。位置按 Run/会话保存，滚动操作不会写入 Orca 已读状态。
- **输入与回执**：全宽输入框配独立发送工具栏，旁边展示快捷键。Enter 换行，Ctrl/Command+Enter 发送；输入法组合输入和重复 keydown 不触发发送。标识与原始 JSON 按需展开，入队结果、不确定发送警告及后续任务入口保持可见。失败/未知发送保留草稿和既有重发保护；回执不表示 worker 已阅读消息。
- **细粒度草稿与状态隔离（`useScopedChatState`）**：
  - 未知指导标记按 Run/Task 隔离，在群聊与私聊间共享。
  - 草稿按 `[runId, mode, recipientTaskId, questionId/dispatchId]` 隔离；切换视图不改投未发正文，迟到响应不会清空其他草稿。
  - 繁忙、错误及回执按 `[runId, recipientTaskId]` 共享，切换视图不能绕过发送中保护。时间线窗口、阅读位置及检查展开按所查看的会话保存。
  - 群聊收件人选择与私聊/群聊各自的会话选择按 Run 隔离。
  - 切换 Run 或会话时草稿独立隔离，绝不发生误发或串话。

## 节点启动配置
位于 Task 私聊同级页签（Task）中的阶段配置面板（`NodePanel`）按依赖顺序列出启动参数：Agent/harness、模型、支持的 effort、工作区放置/环境，以及 OpenCode 界面模式。它强制贯彻 Orca 的不可变任务契约：任务一旦派发，其启动配置即永久锁定。

- **OpenCode 模型选择**：通过可搜索下拉菜单展示本地工作区建议性发现结果，并支持手动自由文本输入（`provider/model[#variant]`）。输入具备即时语法校验反馈，避免写入非法格式。
- **只读锁定字段**：禁用的表单项使用高对比度可读文字、实线边框与柔和背景底色（`opacity: 1; color: var(--ink); background: var(--paper-2); cursor: not-allowed;`）呈现，不再整体淡化为不可读的灰色，亦不再采用过时的虚线边框，锁定原因在相邻提示中清晰可见。
- **挂载持久性与运维跳转**：`NodePanel` 在首次访问 Task 页签时挂载，并在该会话后续的同级页签切换中保持挂载常驻。保留所有阶段操作与运维跳转按钮（`reviewGate`、`reviewFailedStart`、`viewWorkerHistory`），点击可直达对应运维分节（`decisions` 或 `executions`）。
