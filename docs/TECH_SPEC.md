# Technical Specification: Quiet and Safer DAG Viewer

## 1. Architecture summary

This change preserves the existing Express API, React state model, React Flow canvas, Orca authority model, and `.orca-dag.config.json` schema. It removes one unsafe API, reorganizes existing header markup, replaces continuous canvas motion with static visual states, and separates graph geometry work from visual decoration work.

No dependency, credential, service, database, environment variable, or persisted config field is added.

## 2. Public interface changes

### Removed HTTP endpoint

```text
POST /api/reset
Body: { confirmAllRuns: true }
```

The route is removed rather than deprecated. Clients receive the normal Express 404 response. This is intentional because the operation has no Run scope and violates the viewer's safe-redraw workflow.

### Removed frontend function

```ts
resetTasks(): Promise<void>
```

### Updated execution-control interface

`ExecControls` no longer owns a periodic status poll. Its state contract becomes:

```ts
type ExecControlsProps = {
  runId: string;
  taskIds: string[];
  readyCount: number;
  runStatus: RunStatus | null;
  startingRunId: string | null;
  workerHistoryLoading: boolean;
  workerHistoryError: string | null;
  onRunStarting?: (runId: string) => void;
  onRunStartFinished?: (runId: string, status: RunStatus | null) => void;
  onRunStatusChange?: (status: RunStatus | null) => void;
};
```

Start receipts and the one-off post-stop refresh update App through the callbacks. Only App owns the two-second periodic `/api/run-status` request.

## 3. Header layout

### DOM regions

```text
header.topbar
  div.topbar__brand
  div.topbar__run-context
    RunPicker
  div.topbar__status
    RunHealthBadge
    connection chip
```

`RunPicker` continues to own Run loading and creation. Its button label becomes `New Run`. The removed reset action has no replacement because Run creation already implements the safe restart path.

### CSS contract

Desktop:

```css
grid-template-columns: max-content minmax(280px, 1fr) max-content;
```

- Brand and status regions never shrink below their readable content.
- Run context may shrink and its DoodleSelect value uses existing internal text clipping.
- The top bar remains above popovers and does not introduce an overflow clipping ancestor.

Below 1024 px:

```css
grid-template-columns: minmax(0, 1fr) max-content;
grid-template-areas:
  "brand status"
  "run run";
```

Below 620 px:

- Hide the nonessential subtitle.
- Allow the status cluster to wrap inside its own grid cell.
- Run picker uses the full available width.
- The viewport must have no horizontal document overflow at 375 px.

## 4. Motion policy

### Persistent motion

Only `.exec__pulse`, outside `.dag-canvas`, may run indefinitely while a Run is active.

### One-shot motion

- Node entrance, capped at the existing short stagger.
- Status stamp or ripple when a task status changes.
- Dialog, panel, button hover, and button press feedback.

### Removed continuous canvas mechanisms

- `crayon-boil` from task outlines, lead rings, selected lasso, and dependency paths.
- `edge-boil` and the `PencilEdge` WAAPI tracing loop.
- `TaskNode`'s `cycle` state and timeout-driven scribble SVG remount.
- Ready and dispatched aura loops.
- Canvas confetti.
- Decorative gate, legend, progress, and live-thread loops where static color and border already carry the state.

Task scribble geometry remains deterministically generated by task id. It is rendered once as a static fill for dispatched, completed, and failed states. Static SVG filters remain, preserving the crayon material without continuous filter rerasterization.

`prefers-reduced-motion: reduce` continues to disable all transitions and animations and directly reveals final stroke states. No JS timer or WAAPI animation may continue underneath that CSS mode.

## 5. Graph derivation and rendering

### Derived topology

```ts
type GraphTopology = {
  nodes: Array<{ id: string; label: string; parentId: string | null }>;
  dependencyEdges: Array<{ id: string; source: string; target: string }>;
  hierarchyEdges: Array<{ id: string; parent: string; child: string }>;
};
```

The topology input excludes status, selection, harness, worker attempts, and lead ownership. A memoized layout stage runs only for:

```text
topology identity + layout kind + reorgNonce
```

Pseudocode:

```ts
const topology = useMemo(buildTopology, [dag.nodes ids/labels/parents, dag.edges, dag.hierarchy]);
const positioned = useMemo(
  () => applyLayout(layout, topology.nodes, topology.dependencyEdges),
  [topology, layout, reorgNonce],
);
const decoration = useMemo(
  () => deriveStatusSelectionLeadAndHarness(dag, selectedId, leadTaskId, workerRows, attempts, harnessConfig),
  [dag, selectedId, leadTaskId, workerRows, attempts, harnessConfig],
);
reconcileReactFlowState(positioned, decoration, draggedPositions, measuredDimensions);
```

Status still changes edge classes, but it does not change the edge geometry passed to `applyLayout`. Existing dragged-position and measured-dimension preservation remains intact.

### React Flow virtualization

Set:

```tsx
<ReactFlow onlyRenderVisibleElements />
```

This uses the installed `@xyflow/react` 12.4.2 built-in implementation. No custom viewport observer or virtualization package is introduced.

## 6. Poll ownership and visibility

Extract the existing page visibility behavior into:

```ts
// web/src/visibility.ts
export function usePageVisible(): boolean;
```

Consumers:

- `App`: DAG, worker, and Run-status polling.
- `RunPicker`: ten-second Run list polling.
- `RunHealthBadge`: five-second health polling.

When hidden, each consumer clears its interval. On return, each performs one immediate refresh and starts one new interval.

`ActivityPanel` retains its existing hidden-page dirty-flag behavior. The communication center keeps Activity mounted for unread accounting. Operations content mounts only when the Operations tab is active, so `RecoveryPanel` and `RequestAuditPanel` intervals stop naturally on unmount. Chat remains snapshot-driven and is not given a duplicate activity stream.

## 8. Verification

### Automated

```bash
npm run check
```

Server coverage must assert that `/api/reset` is absent and that readiness gating for remaining mutations is unchanged.

### Browser, agent-browser

1. Start the current viewer against the workspace.
2. Capture 1440x900, 1024x768, and 375x812 screenshots.
3. Confirm no horizontal document overflow and no top-bar overlap.
4. Inspect the accessibility snapshot for Run selector, New Run, health, connectivity, and execution controls.
5. Evaluate running animations after two seconds and assert that none target `.dag-canvas`.
6. On a dense Run, zoom into a subset and compare graph counts with mounted `.react-flow__node` and `.react-flow__edge` counts.
7. Observe network traffic for one periodic `/api/run-status` request per two seconds.
8. Hide the page for at least fifteen seconds and confirm periodic requests stop after in-flight work settles.

### Performance evidence

Capture the same ten-second idle and five-second pan traces before and after the change. The post-change trace must show no continuous canvas animation work, no duplicate Run-status polling, and lower scripting and rendering time. Record the trace observations in an implementation evidence document rather than introducing a runtime benchmark feature.

## 9. Failure handling

- If static SVG filters remain expensive on a dense graph, preserve this plan and open a follow-up for a node-count-based texture fallback. Do not restore continuous filter switching.
- If visible-element rendering causes a proven selection or accessibility regression, disable only `onlyRenderVisibleElements`; the motion and layout changes remain independently valid.
- If a responsive state cannot preserve every label, shorten secondary copy before shrinking typography or hiding health state.
