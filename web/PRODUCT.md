## Platform

web

## Users

主要用户是个人开发者：在自己的代码项目中，使用 Orca 监督多个编码智能体并行完成工作。用户负责检查任务依赖和执行进展、处理需要人工判断的事项，并验收执行结果。

本记录中的主要用户、首要目标、设备支持方向及无障碍目标已由用户确认。现有能力与技术边界依据下方列出的仓库文档和实现记录。

## Product Purpose

Orca DAG 将智能体中的规划与查看器中的执行监督分开：智能体生成需求、技术方案和任务 DAG；查看器帮助开发者理解并控制该计划的执行。

首要成功标准是“看清状态，安全介入”，优先于缩短配置步骤或突出已完成成果。用户应能依次回答：现在发生了什么、哪里需要我决策、涉及哪个任务或 worker、有什么证据支持这个状态。快速启动和结果验收是重要能力，但不能以掩盖风险或不确定性为代价。

## Positioning

这是 Orca 的本地 DAG 查看器和外部执行协调器，不是独立的通用智能体聊天产品，也不是 Orca 内嵌插件。规划留在用户选用的智能体中，查看器不嵌入 Agent SDK；执行通过 Orca 的 Run、Task、Dispatch 和 Gate 契约完成。

产品的核心机制是：把依赖图、并行执行、人工决策及可追溯证据放在同一个工作流中，而不是让用户仅凭分散的智能体终端猜测进展。

## Operating Context

- 面向 Orca 管理的项目工作区，查看器以本地服务提供网页；默认绑定回环地址。开发时前端使用 Vite，API 由同仓库的 Express 服务提供。
- 典型流程：在智能体中规划 → 获得 Run ID → 在查看器选择 Run → 配置默认及逐任务执行偏好、并发和工作区 → 确认协调权交接后执行 → 检查状态、报告和待决事项 → 必要时人工介入或在新 Run 中重新规划。
- 规划文档保存在工作区 `.orca-dag/<UTC timestamp>/PRD.md` 和 `TECH_SPEC.md`；查看器配置及执行历史也保存在 `.orca-dag/`。这些属于工作记录，不是可随意清除的临时界面数据。
- 桌面优先：完整执行操作以桌面为主要使用场景；窄屏需要便于查看，不要求与桌面具有同等操作覆盖。
- 界面支持英语与简体中文；服务端错误、原始 CLI 输出和诊断信息保留英文，便于与运行证据核对。

## Capabilities and Constraints

- **查看和执行分开。** Orca 必须运行且工作区已注册。查看与执行具有不同兼容性要求；执行需同时满足已解析 CLI 和实际运行时的就绪条件。执行不可用时仍保留只读导航，不以新 CLI 的版本代替运行时证据。
- **依赖驱动执行。** DAG 展示任务、依赖、层级及状态；协调器在依赖和相关 gate 满足后，按并发容量启动 ready 任务。层级关系不等于调度依赖或操作权限。
- **配置能力有边界。** 支持默认及逐任务 harness、受支持的 model/effort、工作区 placement 和 lane。具体支持取决于智能体、运行时版本与执行位置，以兼容性文档为准；原生支持或技能可安装不等于查看器执行已验证。
- **偏好不可悄然替换。** 任务首次启动后锁定执行偏好；保留不支持的已存配置并说明原因，不自动更换智能体、模型或启动路径。
- **任务定义不可原地修改。** 标题、spec 和依赖的修改需要在新 Run 中重新规划；不提供清空所有任务的 reset 入口，不把全局清理伪装为当前 Run 的操作。
- **不确定不等于结束。** 失联、过期、unknown 或不可读证据，不代表 worker 已退出、操作未发生或结果已成功。不能据此自动重试、替换 worker、释放容量或关闭终端；启动失败也不自动重试。
- **人工决策必须可追溯。** 审批与跨工作区集成保留人工确认；集成 gate 不能代替实际代码集成验证。请求意图、实际回执、worker 活性和清理决定不能合并成一个笼统的“成功”。
- **证据按需展开。** 现有界面提供 Activity、任务级 Chat、Operations、worker 与工作区信息、任务结果、请求审计和能力诊断。保持任务名称与完整标识符之间的可追溯关系，未知值和原始证据不可被友好标签吞掉。
- **本地控制面。** 服务不开放 CORS；写操作需要令牌，自定义执行命令需显式启用。后续界面工作不能削弱这些边界来简化交互。

- npm 发布包名是 `orca-orchestration-launcher`；命令、技能名及运行痕迹保留 `orca-dag`。不能把上游的 npm 包名当作本项目的安装入口。

## Product Principles

1. **先理解，再操作。** 优先解释当前状态、阻塞原因和需要用户判断的事项，再提供与上下文相符的行动。
2. **安全高于速度。** 保留明确的确认、锁定和人工集成边界，不为缩短路径而引入重复执行或破坏性操作。
3. **证据高于推断。** 让结果与其来源、作用范围和时效可核对；缺失或未知保持可见。
4. **尊重用户配置与工作记录。** 不悄然替换执行偏好，不丢弃历史，不把重新规划等同于清空已有工作。
5. **渐进披露，不隐瞒风险。** 首层让个人开发者看清重点，完整标识符和原始诊断可进一步查看；中文与英文保持一致含义。

## Accessibility & Inclusion

- 用户确认以 WCAG 2.2 AA 和键盘可操作为后续设计与实现目标；这不是对当前界面已达标的声明。
- 关键操作需要清晰名称、可见焦点和合理的键盘路径；任务状态、风险与阻塞原因不能只依赖颜色表达。
- 桌面支持完整操作；窄屏查看需要可读的状态、结果和证据，长标识符或诊断内容不应使页面无法使用。
- 无障碍和窄屏能力需要在具体改动中实际验证。本次只确认产品要求，不宣称完成了界面审计。
